# NER-for-ASR-portafolio
Project focused on improving name recognition in audio language models via NER-based prompt conditioning and LoRA fine-tuning (EN/DE)

**Current submission scope: portfolio Steps 1 and 2 only.**
1. Review candidate English datasets and justify the approved choice.
2. Evaluate a pretrained audio language model (Qwen3-ASR) on the approved dataset, **without**
   named-entity context, and report baseline WER/CER.

Status (2026-11-16): dataset approval **pending**. The pipeline passes fixture tests only. No
real-audio inference has run yet, and no portfolio result exists. Later steps (entities, context,
fine-tuning) are deliberately not implemented; see `docs/later_stages.md`.

## Layout
```
config/            one YAML per dataset candidate + cluster route + fixture
src/ner_asr/       reusable code (adapters, selection, transcription, metrics, evaluation)
notebooks/         01_baseline_evaluation.ipynb (generated by scripts/build_notebook.py)
tests/             fixture tests (synthetic tones, fake transcriber)
data/manifests/    fixed selections (small CSVs; commit the approved one)
results/           predictions/ (JSONL, git-ignored) and metrics/ (CSV + summary JSON)
reports/           Step 1-2 report template, reflection prompts
docs/              dataset comparison, lecturer reference, open questions, continuity
```

## Setup

### A. University JupyterHub / Linux GPU (recommended for the real evaluation)
```bash
git clone https://github.com/c-barco/NER-for-ASR-portafolio.git
cd NER-for-ASR-portafolio
python -m venv .venv && source .venv/bin/activate
pip install torch==2.15.0          # or the build matching the cluster CUDA version
pip install -r requirements.txt
python -m ipykernel install --user --name ner-asr --display-name "Python (ner-asr)"
python -m pytest -q
```

### B. Project laptop (Windows 11, CPU only)
The `.venv` already exists in this checkout (Python 3.14.7). **Windows Smart App Control blocks**
some compiled libraries (pyarrow.compute → pandas and `datasets`, numpy.random, spaCy). Tests and the
Kaldi/fixture path work; the Hugging Face streaming adapters do not. Recreate the env with:
```powershell
py -3.14 -m venv .venv
.venv\Scripts\python -m pip install torch==2.15.0 --index-url https://download.pytorch.org/whl/cpu
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m ipykernel install --user --name ner-asr --display-name "Python (ner-asr)"
.venv\Scripts\python -m pytest -q
```
Start Jupyter from the repository root and pick the **Python (ner-asr)** kernel:
```powershell
.venv\Scripts\python -m notebook
```

## Run

All steps take a config file. Defaults are a tiny **pilot** (5 recordings, ≤ 0.02 h).

```bash
# 1) fixed, seeded selection -> data/manifests/<run>_manifest.csv (+ .selection.json)
python -m ner_asr.pipeline select     --config config/<dataset>.yaml
# 2) baseline transcription, no context; resumable (re-run to continue / retry failures)
python -m ner_asr.pipeline transcribe --config config/<dataset>.yaml
# 3) metrics + exports -> results/metrics/<run>_per_recording.csv, <run>_summary.json
python -m ner_asr.pipeline evaluate   --config config/<dataset>.yaml
```
(Run with `PYTHONPATH=src`, or `pip install -e .` once.)

Notebook: open `notebooks/01_baseline_evaluation.ipynb`, set `CONFIG` in section 1 and
`RUN_INFERENCE = True` to download and run the model. Environment variables `NER_ASR_CONFIG`,
`NER_ASR_MODE`, `NER_ASR_RUN_INFERENCE=1` do the same without editing.

### After the dataset is approved
1. Pick the config: `config/voxpopuli_en.yaml`, `config/mls_en.yaml`, `config/common_voice_en.yaml`,
   or `config/cluster_kaldi.yaml` (set `dataset.path` to the lecturer's cluster directory).
2. Run the pilot (above). Check the selection report, listen to 2-3 items, read the worst
   predictions. Each adapter needs this check on first use: none of them has run on real data yet.
3. Decide the model with the team (`config/_model_note.md`) and keep it fixed.

### Full evaluation (only after the duration requirement is clarified)
1. Set `selection.target_hours` in the config (e.g. `40` or the length of the test split).
2. `python -m ner_asr.pipeline all --config config/<dataset>.yaml --mode full`
   * If the split is too short, selection stops with `InsufficientAudioError` instead of mixing splits.
   * Interrupted runs continue where they stopped; re-run the same command.

## Outputs
Per recording: `sample_id, audio_path, duration_seconds, speaker_id, source_split, reference_text,
prediction, reference_norm, prediction_norm, wer, cer, status, error_message, runtime_s,
n_generated_tokens, flag_*` plus the lab_06 columns `wav_path, label, pred_without_context,
wer_without_context, cer_without_context`.
Summary: corpus-level WER/CER, mean/median/min/max per-recording WER/CER, perfect-transcription
rate, success/failure counts and reasons, selected vs evaluated hours, runtime, real-time factor.
